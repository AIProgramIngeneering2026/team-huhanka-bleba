# Grafana Reports

## Название, проблема и для кого

**Название:** Grafana Reports — сервис отчётов из Grafana по расписанию.

**Проблема.** Метрики команды уже собраны в дашбордах Grafana, но регулярный отчёт по ним делается вручную: кто-то открывает дашборд, выставляет период, снимает скриншоты, сводит цифры и рассылает. Это отнимает время и легко пропускается. В Grafana OSS нет встроенной рассылки отчётов по расписанию, а архива прошлых отчётов, к которому могут обращаться другие системы, нет вовсе.

**Решение.** Сервис по расписанию забирает данные выбранных панелей за период, считает итоги и сравнение с прошлым периодом, собирает PDF и доставляет его на почту и/или в хранилище MinIO, откуда отчёт можно выгрузить через API.

**Для кого:**

- **Владелец отчёта** — тимлид, аналитик или менеджер, который настраивает, что и когда попадает в отчёт.
- **Получатель** — руководство и смежные команды, которые читают отчёт и не заходят в Grafana.
- **Внешняя система** — BI, портал или архив, которые забирают готовые отчёты через API.
- **Оператор** — тот, кто следит за запусками, перезапускает упавшие и разбирает ошибки.

## Границы первой версии системы

**Входит в первую версию системы:**

- Создание и правка дашбордов Grafana для тестирования и демонстрации работы сервиса.
- Настройка отчёта: дашборд Grafana по `uid`, панели, значения переменных шаблона, период, расписание, каналы доставки.
- Плановый запуск по cron с часовым поясом и ручной запуск за произвольный период.
- Сбор данных панелей через Grafana HTTP API, итоги и сравнение с прошлым периодом.
- Графики и PDF-отчёт.
- Доставка на почту и/или в MinIO; список отчётов и выгрузка файлов через API.
- Машина состояний Job с журналом переходов, ретраями, отменой и ручным одобрением.
- Автоматически генерируемое описание API (OpenAPI) и клиент.
- Управление пользователями и ролями: базовая аутентификация, проверка сервисом прав доступа.

**Точно не входит в первую версию системы:**

- Хранение бизнес-данных: сервис не ведёт свою копию метрик, всё берётся из Grafana в момент запуска.
- Источники данных в обход Grafana — прямые запросы в БД, Prometheus и т. п.
- Алертинг и мониторинг в реальном времени: это задача самой Grafana.
- Доставка в мессенджеры (Slack, Telegram).
- Текстовый вывод от LLM: место под шаг `Narrating` заложено, но шаг не реализуется.
