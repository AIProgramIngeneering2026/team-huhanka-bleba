# Практика 1 — заявка на проект

## Тема

Сервис, который по расписанию собирает данные из API Grafana, агрегирует их и доставляет отчёт (график + PDF) на почту или во внутреннее хранилище сервиса, откуда его можно выгрузить через API сервиса. Каждый запуск — это Job, проходящий через машину состояний `Scheduled → Collecting → Aggregating → Rendering → Delivered`.

На первом этапе сервис полностью детерминированный. Заранее оставлено место для LLM-шага, который добавит к отчёту текстовый вывод «что изменилось и почему» и пометит аномалии.

## Инженерный скелет

```
┌───────────┐     ┌────────────┐        ┌─────────────┐        ┌-----------------┐
│ Scheduled │────►│ Collecting │───────►│ Aggregating │───────►¦ Narrating (LLM) ¦
└───────────┘     └────────────┘        └──────┬──────┘        └--------┬--------┘
                      LLM выключен             │                        │         
    ┌──────────────────────────────────────────┘      текст готов       │         
    │    ┌──────────────────────────────────────────────────────────────┘         
    │    │                                                                        
┌───▼────▼──┐       ┌------------------┐        ┌───────────┐                     
│ Rendering │──────►¦ AwaitingApproval ¦───────►│ Delivered │                     
└─────┬─────┘       └------------------┘        └───────▲───┘                     
      │                без проверки                     │                         
      └─────────────────────────────────────────────────┘                         
```

Каждый запуск отчёта — запись в таблице jobs, которую воркер проводит по цепочке шагов; каждый переход пишется в job_events.

На любом активном шаге ошибка переводит Job в Retrying с backoff, после исчерпания попыток — в Failed. Из любого неконечного состояния доступен Cancelled.

Компоненты:
- **Источник данных**. Отчёт ссылается на дашборд Grafana по `uid` и список панелей, подставляет переменные шаблона.
- **Движок**. Таблица допустимых переходов; недопустимый переход — ошибка, а не тихая запись в БД.
- **Шаги**. Единый интерфейс `IJobStep.ExecuteAsync(input, ct)`, вход и выход сохраняются в artifacts.
- **Воркер и планировщик**. `RecurringJob` по cron создаёт Job в `Scheduled`, один Job на отчёт и период; ретраи — `AutomaticRetry` с backoff.
- **Доставка**. Канал задаётся в настройках отчёта: почта, MinIO или оба. Файлы кладутся в бакет, ссылка на объект пишется в report_files.
- **API**. Управление отчётами, ручной запуск, статус и история переходов, одобрение в `AwaitingApproval`, список файлов и выгрузка.

## Шов для LLM

LLM подключается как новый шаг `Narrating` между `Aggregating` и `Rendering`; остальные шаги и движок не меняются.
- Контракт шага. Вход — агрегированные таблицы и метрики прошлого периода в JSON; выход — короткий текст и список аномалий `{metric, change, comment}`. Тот же интерфейс `IJobStep.ExecuteAsync(input, ct)`, что у остальных шагов.
- Фича-флаг `narrative_enabled` на отчёт. Если флаг выключен или шаг упал, Job идёт дальше без текста: отчёт с графиками важнее комментария.
- Проверка человеком. Для новых отчётов включается состояние `AwaitingApproval` после `Rendering`: владелец видит текст модели до отправки. Когда качество устоится, проверку можно снять.
- Защита от выдумок. В промпт уходят только посчитанные числа; шаг сверяет все цифры в тексте с входными данными и при расхождении помечает текст как непроверенный.
- Учёт. В `job_events` пишутся модель, версия промпта, токены, стоимость и длительность. Вход и выход шага сохраняются в artifacts для повторного запуска и сравнения промптов.
- Следующие шаги: поиск аномалий, ответы на вопросы по отчёту по тем же артефактам.

## Препятствия

| Препятствие                             | Чем грозит                                                                             | Как снять                                                                                                    |
|-----------------------------------------|----------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------|
| Повторная доставка при ретрае           | Получатель видит одно письмо дважды, в бакете дубли файлов                             | Идемпотентный ключ `job_id + канал + получатель`, детерминированный ключ объекта в MinIO                     |
| Расхождение статусов Hangfire и Job     | Задача в Hangfire завершилась, а Job завис в промежуточном состоянии                   | Бизнес-статус только в `jobs`; переход и постановка следующей задачи в одной транзакции                      |
| Недоступность Grafana или её источников | Job падает на `Collecting`, отчёт не приходит                                          | Polly внутри шага, `AutomaticRetry` Hangfire, уведомление владельцу после исчерпания попыток                 |
| Изменение дашборда в Grafana            | Панель удалили или поменяли запрос — отчёт ломается или показывает другое              | Привязка по `uid` дашборда и `id` панели, проверка при сохранении отчёта, версия дашборда в `artifacts`      |
| Переменные шаблона и макросы            | Запросы панелей содержат `$env`, `$__interval` и т. п., без подстановки не выполняются | Значения переменных в настройках отчёта, подстановка и расчёт интервала на стороне сервиса                   |
| Права и токены Grafana                  | Истёк токен или у сервисного аккаунта нет доступа к папке                              | Отдельный сервисный аккаунт с ролью Viewer, токен в секретах, проверка доступа при сохранении отчёта         |
| Тяжёлые запросы к источникам            | Отчёт нагружает Prometheus или БД за Grafana                                           | Разумный `maxDataPoints` и интервал, отчёты разнесены по времени, лимит параллельных запросов                |
| Пропущенные запуски при простое         | Отчёт за период не сформирован                                                         | Настроить `MisfireHandlingMode` у `RecurringJob`; период брать из запланированного времени, а не из текущего |
| Часовые пояса в расписании              | Отчёт уходит не в то время, период запроса сдвинут                                     | `TimeZoneInfo` в опциях `RecurringJob`, границы периода в UTC при запросе к Grafana                          |
| Тяжёлый рендер PDF                      | Воркер занят надолго, очередь растёт                                                   | Отдельная очередь Hangfire и сервер для `Rendering`, лимит размера данных                                    |
| Рост хранилища MinIO                    | Заканчивается место                                                                    | Lifecycle-политика бакета, срок хранения в настройках отчёта                                                 |
| Утечка ссылок на файлы                  | Отчёт доступен посторонним                                                             | Выгрузка только через API с авторизацией, presigned URL с коротким сроком                                    |
| Расхождение API и клиентов              | Клиент ломается после изменения контракта                                              | Генерация клиента в CI, проверка breaking changes по OpenAPI-диффу                                           |
| Галлюцинации LLM                        | В тексте неверные цифры                                                                | Сверка чисел с входом, `AwaitingApproval`, отчёт без текста при сбое                                         |
| Стоимость и задержки LLM                | Рост расходов, медленные отчёты                                                        | Учёт токенов на Job, лимит на отчёт, кэш по хэшу входа                                                       |
| Нет тестовых данных                     | Нечем проверять агрегацию и промпты                                                    | Записанные ответы Grafana в `tests/`, WireMock.Net, Grafana с тестовым источником в Docker Compose           |
